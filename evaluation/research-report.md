# 연구 보고서 비교 평가

## 실행 방법

각 케이스를 독립 세션에서 실행한다. 공통 요청은 “다음 자료로 도입 여부를 검토하는 팀을 위한 Markdown 보고서를 작성해 줘.”이다. 아래 표에서 한 행의 **입력 자료만** 요청에 붙인다. 모든 수치는 평가용 가상 자료다. 검토 포인트는 평가자만 본다.

| 케이스 | 입력 자료 | 검토 포인트 |
| --- | --- | --- |
| 추론 지연 | 같은 GPU와 요청 100개. 동시성 1에서 p95는 기본 120ms, 후보 100ms. 동시성 8에서 기본 180ms, 후보 210ms. | 동시성에 따른 역전, 운영 부하 확인 |
| 학습 | 같은 평가셋 500건. 기존 모델 420건 정답. 데이터 추가와 2단계 학습을 함께 적용한 모델은 435건 정답. 학습 시간 2→5시간. | 정확도 +3%p, 비용 증가, 변경별 기여도 미상 |
| Ablation | 동일 평가셋 F1(0~1). 기본 0.70, A 0.74, A+B 0.75. B 단독 미측정. | A 위에서 B의 차이와 독립 효과 구분 |
| 오류 분석 | 같은 평가 문서에서 표 필드 오류 18/60, 일반 필드 오류 32/400. | 오류 건수와 오류율에 따른 우선순위 차이 |
| 부정적 결과 | 성공 기준 F1 +0.02. 같은 셋과 seed에서 기본 0.81, 후보 0.80. 반복 측정 없음. | 기준 미달, 실패 원인 단정 방지 |
| 불완전 평가 | 전체 200건 중 기본은 200건 완료, 160건 정답. 후보는 앞 100건만 완료, 88건 정답. 난이도순 정렬. | 전체 개선 판단 보류, 동일 부분집합 비교 필요 |
| 장기 요약 | S1에서 v1 평가셋 F1 0.60→0.68. S2에서 v2 평가셋 baseline 0.72. S3에서 같은 v2 baseline 대비 0.74. | v1과 v2 분리, S2와 S3 계보 연결 |

## 비교 조건

동일 모델과 버전, 추론 설정, 입력, 출력 형식과 시간 예산을 고정한다. 호출마다 로드한 자료를 기록한다. 스킬 본문의 예시 참조 및 검토 단계를 조건에 맞춰 평가용 사본에서만 활성화한다.

| 조건 | 제공 자료 |
| --- | --- |
| A | 도입 전 커밋의 기존 문서화 지침 |
| B | 신규 스킬 본문, 작성 가이드, 템플릿 |
| C | B와 Before/After 예시 2종 |
| D | C와 품질 검토표, 전달 전 수정 단계 |

## 판정과 기록

실행 전 케이스별 필수 사실과 허용 가능한 해석을 확정한다. 예를 들어 불완전 평가에서는 완료 수와 정답 수를 각각 보존하고 비교 범위를 밝혀야 한다. 결과 파일에 run ID, 케이스, 조건, 모델 설정, 입력 버전과 최종 보고서를 연결한다.

| 평가 지표 | 기록 방법 |
| --- | --- |
| 수치 보존율 | 정확히 제시된 필수 수치 수 / 필수 수치 수 |
| 핵심 결과 누락률 | 누락된 필수 사실 수 / 사전 정의한 필수 사실 수 |
| 근거 없는 주장 비율 | 원자료나 계산으로 지지되지 않는 사실 주장 수 / 전체 사실 주장 수 |
| 중복 비율 | 새 정보 없이 반복된 문장 수 / 본문 문장 수 |
| 효율 | 보고서 글자 수, 생성 토큰, 생성 시간과 핵심 결론을 찾는 시간 |
| 독자 선호 | 조건명을 가리고 순서를 무작위화해 같은 케이스의 두 보고서 중 선호 또는 동률과 이유 기록 |

분모가 0이거나 측정할 수 없는 값은 미측정으로 남긴다. 케이스별 결과와 총 분자/분모를 함께 보고한다. 선호도와 길이는 수치 보존과 핵심 결과 누락을 함께 보고 판단한다. 평가를 실행한 뒤에만 개선 효과를 기술한다.
