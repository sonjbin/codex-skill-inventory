# git-tag Skill

## 목적
- 태그를 릴리즈/마일스톤 시점에만 일관되게 생성한다.

## 필수 규칙
- 태그는 명시적으로 요청된 경우에만 생성한다.
- 사소한 변경마다 태그를 만들지 않는다.
- 가능한 경우 안정 상태(기본 브랜치 병합 후)에서 태그 생성 여부를 우선 검토한다.

## 네이밍 규칙
- 권장: Semantic Versioning `v<MAJOR>.<MINOR>.<PATCH>`
- 선택: 실험/데모 태그
  - `exp-<name>-v1`
  - `demo-<name>-YYYY-MM`

## 실행 절차
1. 태그 생성 필요성을 확인한다.
- 완료 조건: 태그 목적(릴리즈/공유/재현성 고정)이 명확함.
- 검증 방법: 사용자 요청 문맥 또는 확인 응답.

2. 태그 이름 규칙 적합성을 점검한다.
- 완료 조건: semver 또는 실험/데모 규칙 중 하나를 충족.
- 검증 방법: 태그 문자열 패턴 점검.

3. 태그 생성 전 대상 커밋을 확인한다.
- 완료 조건: 태그 대상 commit SHA가 확정됨.
- 검증 방법: `git rev-parse --short HEAD` 또는 지정 SHA 확인.

4. 태그 생성 후 중복/반영 상태를 검증한다.
- 완료 조건: 로컬 태그 목록에서 식별 가능.
- 검증 방법: `git tag --list` 또는 `git show <tag>`.

## 중단 조건
- 태그 생성 요청이 명시적이지 않은 경우
- 태그 이름이 규칙을 만족하지 않는 경우
- 대상 커밋이 불명확한 경우
