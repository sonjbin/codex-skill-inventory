# 문서 작성 가이드라인 (agents.md용)

파이프라인/hook/모듈 설명 문서를 작성할 때 따르는 공통 규칙. 새 문서를 쓰거나 기존 문서를 정리할 때 이 기준을 따름.

## 1. 문체

* 모든 서술은 **명사형 종결**로 마무리. `~함`, `~됨`, `~임` 대신 `생성`, `추출`, `정규화`, `저장`, `확인`처럼 명사로 끝냄
* "만듦", "만든다" 같은 표현은 사용하지 않음 → `생성`, `구성`, `작성` 등으로 대체
* 문장은 짧게. 한 bullet에 한 동작만 담음
* 불필요한 수식어, 완곡한 표현 제거. 사실만 전달
* 존댓말 금지, 구어체 금지. 기술 문서 톤 유지

**변환 예시**

| 지양 | 지향 |
|---|---|
| ~~VLM 요청을 만듦~~ | VLM 요청 생성 |
| ~~KV 값을 정규화함~~ | KV 값 정규화 |
| ~~결과를 저장한다~~ | 결과 저장 |
| ~~~를 확인할 수 있음~~ | ~ 확인 |

## 2. 구조 템플릿

각 컴포넌트(hook/모듈/단계)는 아래 순서로 기술.

```
## N. 컴포넌트명

**역할:** 한 줄 요약 (무엇을 하는지, 명사형 종결)

**처리 내용**
* 처리 단계를 순서대로 bullet 나열
* 조건/설정값이 있으면 괄호나 하위 bullet로 병기
  * 하위 항목은 들여쓰기로 구분

**출력 구조** (필요 시)
코드블록으로 JSON/YAML 예시 제공

**데모 예시** (필요 시)
실제 값 기반 예시를 코드블록으로 제공
```

* 컴포넌트 간 구분은 `---` 로 명확히 분리
* 컴포넌트가 여러 개면 문서 상단에 전체 흐름을 2~3단계로 요약하고, 이어서 hook 실행 순서를 코드블록 리스트로 제시

## 3. 코드/설정/필드명 표기

* 함수명, hook명, 파일 경로, 설정 키, JSON 필드명은 항상 백틱(`` ` ``)으로 감쌈
  * 예: `` `VLMMultiPageKVPreprocessHook` ``, `` `page_index_base` ``
* 실제 JSON/YAML 데이터는 별도 코드블록(```json`` / ```yaml``)으로 분리하고 본문 문장에 섞지 않음
* 설정값과 그 의미를 함께 적을 때는 `기본값 X이므로 Y가 됨` 형식으로 인과관계를 명시

## 4. 예시 데이터 사용 원칙

* 실제 데모/샘플 데이터가 있으면 반드시 코드블록으로 포함 (텍스트 설명만으로 대체하지 않음)
* 예시는 문서에서 설명한 필드/구조와 1:1로 매칭되게 배치 (설명 직후에 예시 코드블록 배치)
* 예시 데이터는 원본 값 그대로 사용, 임의로 요약하거나 변형하지 않음

## 5. 표/강조 사용 기준

* 비교, 매핑, 옵션 목록처럼 2차원 정보는 표로 정리
* 핵심 용어나 hook 이름은 최초 언급 시 **볼드** 처리 가능하나 남용하지 않음
* 인용구(`>`)는 "이 결과는 아직 최종이 아님" 같은 주의사항/보충 설명에만 제한적으로 사용

## 6. 흐름/의존관계 설명

* 단계 간 데이터가 어떻게 이어지는지(입력→출력) 명시
* 반복 구조(예: 페이지별 반복 처리)가 있으면 별도 소제목으로 분리해 설명
* 문서 마지막에는 "완료 조건"과 "검증 방법"을 분리해서 명시
  * 완료 조건: 이 문서가 갖춰야 할 내용 체크리스트
  * 검증 방법: 실제 코드/설정 파일과 문서 내용을 대조하는 방법
